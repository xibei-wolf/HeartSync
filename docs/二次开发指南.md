# 二次开发指南

> 面向「以后想继续维护这个项目」的你。
> 本地工程删掉也不影响 —— GitHub 上的仓库就是唯一真源。

---

## 一、标准工作流

```
拉取最新  →  改代码  →  构建验证  →  提交推送
  git pull    (Android Studio)   ./gradlew assembleDebug   git push
```

### 1. 拉取最新代码

```bash
cd HeartSync
git pull
```

### 2. 改代码

用 Android Studio 打开**仓库根目录**（不要进 `app/`），正常改。

### 3. 构建验证

```bash
./gradlew assembleDebug
```

产物在 `app/build/outputs/apk/debug/app-debug.apk`。

### 4. 提交推送

```bash
git add -A
git commit -m "feat: 新增 XXX 功能"
git push
```

推送后 GitHub 上立刻可见，约 1~2 分钟后仓库页也会刷新。

## 二、从零重新开始（本地已删除的情况）

### 最省事：双击脚本

克隆仓库根目录下的 **`重新开始.bat`**，它会自动完成：

1. 从 GitHub 克隆 `xibei-wolf/HeartSync` 到当前目录下的 `HeartSync` 子目录
2. 自动生成 `local.properties`（写入你机器上的 SDK 路径）
3. 自动生成 `server/.env`（从 `.env.example` 复制，Key 留空待填）
4. 校验 git / java / adb 是否就绪，并打印后续步骤

> 脚本是**纯英文输出**的 —— Windows 的 cmd.exe 在处理 UTF-8 中文批处理时有已知的解析缺陷（见下方「批处理脚本的坑」），用英文可以保证在任何机器上 100% 可靠。完整中文说明在本文档里。

### 手动版

```bash
git clone git@github.com:xibei-wolf/HeartSync.git
cd HeartSync

# 1) 告诉 Gradle 你的 SDK 在哪（Windows 路径）
echo "sdk.dir=C:/Android/Sdk" > local.properties

# 2) 服务端配置（可选，填了才有真实 AI 能力）
cp server/.env.example server/.env
# 然后编辑 server/.env，填入 AI_API_KEY

# 3) 构建
./gradlew assembleDebug
```

> `local.properties` 和 `server/.env` **不在 Git 仓库里** —— 前者是你机器的私有路径，后者含 API Key。这是故意的，见下文「安全设计」。

## 三、这份仓库里没有什么（以及为什么）

| 缺失的文件 | 原因 | 怎么补回来 |
|---|---|---|
| `local.properties` | 含你机器的 SDK 绝对路径，换台电脑就失效 | 脚本自动生成，或手动一行写入 |
| `server/.env` | **含真实 API Key**，提交上去等于公开泄露 | `cp server/.env.example server/.env` 后填 Key |
| `app/build/` | 构建产物，每次都会重新生成 | 跑一次 `./gradlew assembleDebug` |
| `.gradle/`、`.idea/` | 缓存与 IDE 配置 | 同上，自动重建 |
| `local.properties` 里的 `sdk.dir` | 同上 | — |

> ⚠️ **`.env` 千万别提交**。`.gitignore` 已经挡住了，但如果你手动 `git add -f` 强行加进去，Key 就会公开。Gitee / GitHub 仓库一旦公开，Key 泄露 = 别人盗刷你的额度。

## 四、常见坑（都是实际踩过的）

### ① 中文路径下 AGP 拒绝构建

项目已在 `gradle.properties` 里加了 `android.overridePathCheck=true`，**中文路径下可以直接构建**。如果仍然报错，把项目挪到纯英文路径再试。

### ② 同一次命令里 `clean` 和 `assembleDebug` 连写会首跑失败

```bash
./gradlew clean assembleDebug    # ❌ 首跑可能失败（configuration cache 与文件锁竞争）
./gradlew clean                  # ✅ 分开跑
./gradlew assembleDebug          # ✅
```

重跑一次通常就过了，不是代码问题。

### ③ `LoginActivity` / `MainActivity` 拉不起来

这两个 Activity 是 `exported="false"`，adb 从外部拉不动，必须走启动页：

```bash
adb shell am start -n com.heartsync.app/.activity.SplashActivity
```

### ④ 模拟器开了两个实例，端口被占

症状：`adb devices` 能看到设备，但**没有窗口**。

```bash
adb emu kill     # 关掉占端口的实例，再重新启动
```

### ⑤ 健康指数显示的是动画中间值

首页分数是逐帧递增的（每 16ms 一帧）。**截图前等 2~4 秒**，否则会抓到中间值（比如本该 84 分，截到 68 分）。

### ⑥ 服务端测试结果异常

`test_api.js` 会自己 spawn 一个服务端子进程。**跑测试前确认 8080 端口空闲**，否则新进程起不来，测试会打到旧实例上导致结论失真。

### ⑦ 服务端测试在「配了 API Key」的环境下会失败 1 个用例

`未配置 AI_API_KEY 时返回离线兜底` 这条用例依赖「没有 Key」。现在测试脚本已显式置 `AI_FORCE_OFFLINE=true`，所以有无 Key 都能稳定 44/44 通过。

### ⑧ 批处理脚本的坑（写 `.bat` 时必看）

这几个坑全都在写 `重新开始.bat` 时实测踩出来的，改脚本前务必了解：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **LF 换行** | `if (...) else (...)` 多行块直接报「此时不应有」语法错误 | `.bat` 必须用 **CRLF**。仓库的 `.gitattributes` 已配 `*.bat text eol=crlf`，git 检出时会自动转好 |
| **`title` 命令** | 长批处理里执行 `title` 会破坏 cmd 的文件位置跟踪，**后续行被截断**（表现为 `'xxx' 不是内部或外部命令`） | **不要在 `.bat` 里用 `title`** |
| **UTF-8 中文** | 与上面的问题叠加时，中文 echo 行会被拆成两半 | 批处理正文用**纯 ASCII**，中文说明放 Markdown |
| **嵌套 if 块** | 嵌套括号在 cmd 里解析脆弱 | 用 `goto :label` + 平铺结构代替嵌套 |
| **`%~dp0` 尾反斜杠** | `"%~dp0"` 展开成 `C:\path\`，结尾的 `\"` 被 git 当成路径的一部分 → `Invalid argument` | 用 `for %%I in ("%~dp0.") do set "BASE=%%~fI"` 规范化 |
| **echo 里的 `&`** | `echo cd server && node server.js` 里的 `&&` 会被当成命令执行 | 转义成 `^&^&` |
| **`chcp 65001`** | 与 UTF-8 中文混用时可能因代码页切换时机导致解析错位 | 若正文纯 ASCII，可保留 `chcp 65001` 无害 |

> 这些坑都不是「你的代码有问题」，是 cmd.exe 本身的老毛病。实测结论：**纯 ASCII + CRLF + `goto` 平铺 + 无 `title`** = 稳定可靠。

## 五、常见修改场景

### 想改 App 界面
1. 布局：`app/src/main/res/layout/*.xml`
2. 颜色 / 尺寸 / 字符串：`app/src/main/res/values/`
3. 图标：`app/src/main/res/drawable/`（矢量 XML，改完跑 `python tools/gen_launcher_icons.py` 重新生成各密度 PNG）

### 想加一个新页面
1. 在 `app/src/main/java/com/heartsync/app/activity/` 新建 Activity
2. 在 `AndroidManifest.xml` 注册（记得 `android:exported` 属性，Android 12+ 必填）
3. 布局放 `app/src/main/res/layout/`

### 想加一个服务端接口
1. 在 `server/server.js` 的 `ROUTES` 表注册路径
2. 写处理函数
3. 在 `server/test_api.js` 补一条用例
4. 跑 `node test_api.js` 确认 44+N 全通过

### 想更新 README 里的截图
```bash
# 截图后放进 docs/screenshots/，然后
git add docs/screenshots/ && git commit -m "docs: 更新截图" && git push
```
记得同步更新 README 里的图片引用顺序。

## 七、安全设计（改这个项目时请保持）

| 保护对象 | 做法 |
|---|---|
| 大模型 API Key | 只放 `server/.env` 或 App 本地 `SharedPreferences`，**绝不进仓库** |
| 用户密码 | SQLite 里存 SHA-256 哈希，不存明文 |
| 本机路径 | `local.properties` 不提交 |
| 构建产物 | `build/`、`.gradle/` 不提交 |
| 换行符 | `.gitattributes` 统一 LF，`*.bat` 用 CRLF —— 避免 Windows/macOS 混用产生整文件差异 |

提交前扫一眼：

```bash
git grep -n "sk-" -- . ':!server/README.md' ':!server/.env.example'
```

输出为空 = 没有 Key 泄漏。
